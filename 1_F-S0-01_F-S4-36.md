## F-S0-01 — `app.config.ts` : JwtInterceptor non enregistré

**🔴 CRITIQUE — Cassant en production immédiat**

**Anomalie exacte :** `withInterceptorsFromDi()` est utilisé dans `provideHttpClient()` mais `JwtInterceptor` n'est **jamais déclaré** dans les `providers` de `appConfig`. Résultat : toutes les requêtes HTTP partent sans header `Authorization: Bearer <token>` → 401 systématiques sur l'ensemble de l'API.

**Correctif — Option A (si S0-04 est fait en premier — migration fonctionnelle) :**

```typescript
// app.config.ts
import { jwtInterceptor } from './core/interceptors/jwt.interceptor';

provideHttpClient(
  withInterceptors([jwtInterceptor])
)
// Supprimer withInterceptorsFromDi()
```

**Correctif — Option B (si S0-04 n'est PAS encore fait — classe legacy temporaire) :**

```typescript
// app.config.ts
import { JwtInterceptor } from './core/interceptors/jwt.interceptor';
import { HTTP_INTERCEPTORS } from '@angular/common/http';

providers: [
  provideHttpClient(withInterceptorsFromDi()),
  { provide: HTTP_INTERCEPTORS, useClass: JwtInterceptor, multi: true }
]
```

> ⚠️ **Ordre d'exécution :** Appliquer Option B d'abord, puis F-S0-04 (migration fonctionnelle), puis basculer vers Option A. Ne jamais laisser les deux simultanément.

## F-S0-02 — `jwt.interceptor.ts` : Pattern classe legacy Angular

**🔴 CRITIQUE**

**Anomalie exacte :** L'intercepteur utilise `@Injectable() + class JwtInterceptor implements HttpInterceptor` avec `constructor(private authService: AuthService)` — pattern Angular pré-14 incompatible avec l'approche `withInterceptors([])` de Angular 17.

**Correctif :**

```typescript
// core/interceptors/jwt.interceptor.ts
import { HttpInterceptorFn, HttpRequest, HttpHandlerFn } from '@angular/common/http';
import { inject } from '@angular/core';
import { Router } from '@angular/router';
import { catchError, throwError } from 'rxjs';
import { AuthService } from '../services/auth.service';

export const jwtInterceptor: HttpInterceptorFn = (req: HttpRequest<unknown>, next: HttpHandlerFn) => {
  const authService = inject(AuthService);
  const router = inject(Router);

  const token = authService.getToken();
  const authReq = token
    ? req.clone({ setHeaders: { Authorization: `Bearer ${token}` } })
    : req;

  return next(authReq).pipe(
    catchError(err => {
      if (err.status === 401) {
        authService.logout();
        router.navigate(['/login']);
      }
      return throwError(() => err);
    })
  );
};
```

```typescript
  return sessionStorage.getItem(this.TOKEN_KEY);

  sessionStorage.removeItem(this.TOKEN_KEY);
  this.logoutSubject$.next(); // cf. F-S0-07
  inject(Router).navigate(['/login']);
}
```

## F-S0-06 — `auth.service.ts` : `isAuthenticated()` ne vérifie pas l'expiration

**🔴 CRITIQUE**

**Anomalie exacte :** `isAuthenticated()` vérifie uniquement `getToken() !== null`. Un token expiré (champ `exp` dans le payload JWT dépassé) retourne `true` → l'utilisateur est considéré authentifié alors que ses appels API seront tous en 401.

**Correctif :**

```typescript
// core/services/auth.service.ts
// Installer jwt-decode : npm install jwt-decode
import { jwtDecode } from 'jwt-decode';

interface JwtPayload {
  exp: number;
  sub: string;
}

isAuthenticated(): boolean {
  const token = this.getToken();
  if (!token) return false;
  try {
    const payload = jwtDecode<JwtPayload>(token);
    return payload.exp > Date.now() / 1000;
  } catch {
    return false;
  }
}
```
